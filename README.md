## Current prerelease

ThinkControl `v0.1.0-alpha.6` is the current prerelease. Windows controls are device-neutral where possible; low-level fan, EC and keyboard writes stay capability-gated and are only enabled after the relevant provider/profile checks pass.

The ThinkPad X9-15 Gen 1 machine types `21Q6` and `21Q7` are the current physically verified low-level reference profile. ThinkControl targets Windows 11 x64 and .NET 10.

## Interface

ThinkControl has two connected surfaces: a compact notification-area flyout for everyday controls and a resizable Advanced window for detailed tuning and telemetry. ## Touchpad

The Touchpad page receives Precision Touchpad input for live visualization. A red point follows the real contact position and a fading trail makes movement easy to understand while configuring zones. Touchpad regions brighten on hover and turn red only when selected.

Default edge actions:

| Edge | Default action |
| --- | --- |
| Left | Volume |
| Right | Brightness |
| Top | Media seek |
| Bottom | Off |

Available actions include volume, brightness, media seek, previous/next track, play/pause, mute, Task View, Show Desktop, keyboard backlight and performance mode.

Media seek coalesces position writes instead of sending one request for every touch frame. Slow movement remains precise while faster/longer swipes progressively increase the seek distance, with a final target flush when the gesture ends. This avoids stacking overlapping seek requests in players such as Spotify.

During a gesture ThinkControl shows the useful value, not only millimetres: for example `Volume · 58% · +5%`, `Brightness · 72% · -3%` or `Media seek · +18.4 s`. Configuration sliders also show their current value and signed difference from default. Small reset icons appear beside sliders only when that control differs from its default.

The gesture OSD uses the same ThinkControl theme, optional light transparency and left/center/right placement above the Windows work area. Volume/brightness controls are interactive instead of passive notifications.

Haptic feedback uses discrete Windows-like levels rather than misleading arbitrary percentages. Click sensitivity is presented intuitively from **Light → Medium → Firm**.

## Hardware compatibility and recovery

The normal UI runs as the signed-in user. Privileged operations are isolated in `ThinkControl.Service` and exposed through semantic named-pipe commands rather than arbitrary EC/IOCTL passthrough.

Provider discovery is separated so a slow first sensor scan cannot make a running Windows service appear offline. The UI receives a fast cached service status while LibreHardwareMonitor/PawnIO/EC/keyboard discovery continues in the background.

- Windows display, power, audio and battery features remain available independently of low-level hardware providers.
- LibreHardwareMonitor/PawnIO sensor discovery is read-only and can recover/recycle after a driver becomes available.
- Fan RPM may come from any trustworthy discovered telemetry provider.
- Lenovo keyboard control activates only after a known provider contract responds correctly.
- Direct EC fan writes remain restricted to reviewed device profiles.

Hardware Setup no longer ends at a generic disabled message. It shows the ThinkControl service, PawnIO hardware-access state and Lenovo platform integration separately, with the relevant repair/install/retry action. PawnIO is treated as ready only when its driver device and the LibreHardwareMonitor EC module are actually reachable.

For an unverified laptop, ThinkControl can prepare a **hardware-only device support report**. The flow explains `Detect → Compare → New data → Review → Share`, and sharing only becomes relevant after useful provider/capability information has been found. Reports exclude serial numbers, Windows usernames, hostnames, personal paths and raw personal logs; nothing is silently uploaded.

See [Device support](docs/DEVICE-SUPPORT.md), [Cooling design](docs/COOLING-DESIGN.md) and [Hardware safety](docs/HARDWARE-SAFETY.md).

## Audio and Dolby

Audio now includes a live Windows system-volume slider, output-device state and mute control.

For Dolby, ThinkControl exposes Dynamic, Movie, Music, Game and Voice. It first probes the registered Dolby DAX backend. When direct control is exposed, ThinkControl switches profiles without opening Dolby Access and performs readable-state checks where possible.

The Intelligent Equalizer choices match Lenovo/Dolby behavior: **Balanced, Detailed, Warm and Off**. They are tonal subprofiles of the selected Dolby processing mode, not unrelated game presets. ThinkControl tries both the exposed subprofile route and DAX IEQ setter before reporting the control unavailable. Dolby Access only opens when the user explicitly chooses **Open Dolby Access**.

## Battery history

ThinkControl stores a small local battery history rather than retaining large telemetry buffers in RAM. Charge and discharge sessions are tracked independently.

A session can include duration, start/end percentage, Wh added/used, average and peak power, percent-per-hour charge/drain and available temperature/capacity context. Clicking a session opens a reusable ThinkControl telemetry detail sheet with stats and a graph; the same component can be reused for sensor history later.

Recent discharge-rate history acts only as a bounded stabilising input for battery-life ETA. Live telemetry remains dominant, so an old heavy workload does not permanently distort the estimate.

## Updates and installer

ThinkControl checks GitHub Releases automatically. The Updates page shows when it was **last checked**; a manual check switches into a visible `Checking…` loading state and updates the timestamp only when the request completes.

When a newer release is found, ThinkControl downloads the installer to a temporary location, verifies it against `SHA256SUMS.txt`, and starts the verified setup in update mode. The normal update path does not send the user to a browser.

The installer recognises an existing ThinkControl installation, uses update wording, skips first-install shortcut questions, can close a running tray/UI instance, safely stops/re-registers the hardware service and can relaunch the app after an in-app update.

The setup itself stays small: the release uses a web bootstrap installer plus a separately verified application payload.

Download from [Releases](https://github.com/Hugowhitee/ThinkControl/releases):

```text
ThinkControl-Setup-0.1.0-alpha.6.exe
ThinkControl-Payload-0.1.0-alpha.6.zip
SHA256SUMS.txt
```

## Reset and native Windows links

Relevant Advanced pages have a small local reset action. Individual sliders expose a compact reset-to-default icon when changed. **Reset all** lives separately in Settings as a clearly global action with confirmation instead of looking like another page reset button.

Controls that are also owned by Windows expose a subtle contextual **Open Windows settings** link where it is useful, such as Display and Touchpad, rather than duplicating links everywhere.

## Tray, notifications and Compact

ThinkControl is single-instance. Launching it again activates the existing process instead of creating another notification-area icon. Clicking the tray icon toggles the Compact surface open/closed, while desktop/start-menu launches restore the normal Advanced taskbar window when appropriate.

The notification-area icon is rendered from the same ThinkControl BrandMark used by the app instead of the obsolete tray artwork. Advanced and Compact share a notification inbox; hardware-attention messages lead to the relevant recovery action instead of immediately forcing Hardware Setup open.

Compact keeps quick controls concise and uses the same themed menu surface as Advanced rather than a default white Windows dropdown.

## Build and validation

Windows CI restores, builds, runs Core tests and renders real WPF snapshots at fixed Compact and Advanced sizes. Packaging CI builds the UI/service payload, verifies canonical branding, creates the small web bootstrapper and performs an actual silent **install → service Running → uninstall → cleanup** lifecycle test.

```powershell
dotnet restore ThinkControl.slnx
dotnet build ThinkControl.slnx -c Release
.\tools\visual-qa.ps1
```

Automated CI cannot prove physical laptop behavior. RPM, EC fan ownership, keyboard readback, touchpad HID reports, Dolby DAX behavior and haptic response still require real-device verification; ThinkControl reports those states instead of pretending CI validated them.
