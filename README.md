## ThinkControl alpha.30

ThinkControl is a lightweight Windows 10/11 companion that starts with verified Lenovo/ThinkPad hardware support while keeping Windows-generic capabilities and provider contracts usable across other laptops. It combines controls normally spread across Windows Settings, OEM utilities and monitoring tools into a fast Compact view and a resizable Full view.

**Current prerelease candidate:** `v0.1.0-alpha.30`

**Verified low-level reference:** ThinkPad X9-15 Gen 1 (`21Q6` / `21Q7`)  
**Platform:** Windows 10 version 2004 (build 19041) or newer, x64 · .NET 10

Windows-safe controls can work on more systems, while direct EC/fan and OEM controls stay capability-gated. ThinkControl does not invent RPM values, PWM percentages, sensor readings or guessed hardware registers.

ThinkControl has two primary surfaces:

- **Full view** — Home, Performance, Fans, Display, Audio, Keyboard, Battery, Touchpad, System, Updates and Settings.

The release pipeline renders the real WPF interface across dark/light themes and multiple viewport sizes. It also runs real Compact ↔ Full lifecycle smoke tests so shell regressions are not hidden by static screenshots.

## Install

Download the newest setup from **[GitHub Releases](https://github.com/Hugowhitee/ThinkControl/releases)**:

```text
ThinkControl-Setup-0.1.0-alpha.30.exe
```

For a normal install, Setup is the only file you need. A clean interactive install lets you choose the install location. Updates preserve the existing location automatically. Each public prerelease also includes the updater payload, `SHA256SUMS.txt` and `ui-overview.png`.

Updates are explicit: ThinkControl downloads Setup + Payload + checksums, verifies SHA-256, then asks Windows for elevation. Background update checks never install or open UAC by themselves.

The release gate exercises a clean custom-location install, hardware-service start and IPC, an in-place update without passing the location again, compatibility with the older alpha.14 updater path, and a full uninstall cleanup.

## What alpha.30 changes

Alpha.30 focuses on interaction reliability, safer fan experimentation, touchpad intent and installer lifecycle hardening based on real alpha.29 use.

- **Compact stays open when another app gets focus.** Clicking Chrome, a browser tab or another application no longer schedules a hidden deactivation auto-close; only explicit close, tray-toggle or Compact/Full transitions hide it.
- **Compact tray activation remains guarded.** Input-priority activation plus a short double-click gate keeps impatient repeated tray clicks from opening and immediately closing the utility window.
- **Compact selectors are no longer clipped.** The shared ComboBox sizing contract gives quick controls enough vertical room for their complete border and content.
- **Home battery information is cleaner.** ETA lives inside the Battery metric, the gauge is slightly larger and better positioned, and normal card clicks no longer throw obstructive hover popups.
- **Touchpad Track control is more reliable.** Previous / Next / Play-Pause prefers the active Windows media session with media-key fallback where needed.
- **Center Play/Pause has an explicit safe zone.** It requires a bounded low-travel hold-and-release inside the outlined center area; taps, normal swipes and long passive rests are rejected.
- **Corner launch zones are separate from precision edge gestures.** Optional top-left/top-right zones can launch Compact or Full view, default to Off and require deliberate diagonal inward intent so normal scrolling or edge movement does nothing.
- **Manual fan output is temporary by design.** Manual percent and verified raw EC-step tests remember the previous cooling profile, expose `End test`, auto-restore after 30 seconds and restore when leaving Fans; firmware Auto is the fallback if restoration fails.
- **Raw EC UI stays provider-gated.** X9 calibration/raw EC stepping is not inherited by a generic fan provider merely because that provider supports fan control.
- **Fan safety is part of visual QA.** CI renders a dedicated temporary-manual-test state in addition to the active curve and unavailable-provider states.
- **Installer location handling is hardened.** Clean installs expose the destination page, while existing/update installs reuse Inno Setup's remembered application directory instead of assuming Program Files.
- **Uninstall cleanup is broader.** The uninstaller stops/removes the service and clears ThinkControl-owned install/update state plus bounded local application/service data for the normal install lifecycle.
- **Installer failures are diagnosable.** Reliability smoke tests preserve per-phase Inno logs and print the useful tail when Setup exits unexpectedly.
- **Release validation remains hardware-cautious.** CI proves software, UI, updater and installer contracts; physical fan, EC, haptic and OEM behavior is claimed only where the target provider/device has actually been validated.

| **Settings** | App behavior, appearance, diagnostics/privacy, battery-history retention and reset controls |

## Hardware safety and device support

ThinkControl grows support from broad to specific:

`Windows generic → OEM generic → product family → exact model`

Profiles decide which providers are reasonable to probe. Providers own implementation, readback, lifecycle and write safety. Low-level controls remain unavailable until the exact capability is detected and validated.

On the verified X9-15 profile:

- direct fan writes stay restricted to reviewed machine types;
- writes are read back and supervised;
- failed/disposed manual ownership returns to Lenovo/OEM Auto where supported;
- real provider telemetry is preferred over fallback probes;
- sensor/provider failure is reported explicitly rather than replaced by synthetic values.

On an unverified laptop, ThinkControl can quietly learn provider/control compatibility while the user naturally exercises the app. Known devices skip that compatibility-learning workflow and load normally. A future shared device-profile service will require repeated independent evidence before promoting hardware-specific behavior; that commercial/cloud lifecycle is not part of alpha.30.

See **[Device support](docs/DEVICE-SUPPORT.md)** and **[Hardware safety](docs/HARDWARE-SAFETY.md)**.

## Diagnostics and privacy

Diagnostics are separated into three concerns:

- **Compatibility learning** for an unknown device, until the useful evidence is stable.
- **Crash recovery**, stored locally so a fatal crash can be reviewed on the next healthy launch.
- **Troubleshooting data**, kept local and bounded for support/debugging.

Compatibility reports exclude serial numbers, Windows usernames, hostnames, personal paths and raw personal logs. In alpha.30 nothing is uploaded automatically. Opening a pre-filled GitHub report is an explicit action, and the same semantic report is remembered as handled until new evidence appears.

See **[Diagnostics & privacy](docs/DIAGNOSTICS.md)**.

## Touchpad behavior

Continuous actions are bounded and coalesced rather than issuing an OS write for every raw touch frame. Media seeking uses an accumulated target and controlled write cadence so slow movement can stay precise without flooding media sessions.

The visual trail represents actual continuous contact. A new contact starts a new segment; an implausibly large physical jump also breaks the segment instead of drawing a fake connecting line.

Previous/Next can optionally expose Play/Pause in the center. A skip gesture wins first; center Play/Pause only commits after deliberate low-travel hold-and-release inside its visible center zone. Optional corner launches use a separate recognizer and never reuse the precision edge-action model.

## Audio and Dolby

ThinkControl keeps the normal Windows audio path usable even if Dolby integration is unavailable. Output/input discovery is performed away from the UI thread and coalesced so revisiting Audio does not repeatedly block the page on CoreAudio COM activation.

Direct Dolby controls are enabled only when the installed DAX provider exposes a semantic interface ThinkControl can verify. Unsupported DAX builds remain explicit; ThinkControl does not guess private Dolby profile IDs.

## Development and validation

Windows CI restores and builds the solution, runs core tests, executes the real shell-transition smoke and renders the WPF visual-QA matrix before packaging.

```powershell
dotnet restore ThinkControl.slnx
dotnet build ThinkControl.slnx -c Release
.\tools\visual-qa.ps1
```

Packaging and installer workflows additionally validate payload construction, custom-location clean install, service start/IPC, in-place updater compatibility and uninstall cleanup before a prerelease is promoted.

Automated CI cannot prove physical-device behavior. Fan ownership/RPM, OEM keyboard readback, touchpad HID behavior, Dolby DAX behavior and haptic response still require validation on the actual target hardware before that exact driver/firmware combination is treated as physically confirmed.
