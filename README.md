## ThinkControl alpha.27

ThinkControl is a lightweight Windows 10/11 companion focused first on Lenovo and ThinkPad laptops. It combines controls normally spread across Windows Settings, Lenovo utilities and monitoring tools into a fast Compact view and a resizable Full view.

**Current prerelease:** `v0.1.0-alpha.27`  
**Verified low-level reference:** ThinkPad X9-15 Gen 1 (`21Q6` / `21Q7`)  
**Platform:** Windows 10 version 2004 (build 19041) or newer, x64 · .NET 10

Windows-safe controls can work on more systems, while direct EC/fan and OEM controls stay capability-gated. ThinkControl does not invent RPM values, PWM percentages, sensor readings or guessed hardware registers.

ThinkControl has two primary surfaces:

- **Compact view** — quick telemetry and the controls you change most often.
- **Full view** — Home, Performance, Fans, Display, Audio, Keyboard, Battery, Touchpad, System, Updates and Settings.

The release pipeline renders the real WPF interface across dark/light themes and multiple viewport sizes. It also runs real Compact ↔ Full lifecycle smoke tests so shell regressions are not hidden by static screenshots.

## Install

Download the newest setup from **[GitHub Releases](https://github.com/Hugowhitee/ThinkControl/releases)**:

```text
ThinkControl-Setup-0.1.0-alpha.27.exe
```

For a normal install, Setup is the only file you need. Each public prerelease also includes the updater payload, `SHA256SUMS.txt` and `ui-overview.png`.

Updates are explicit: ThinkControl downloads Setup + Payload + checksums, verifies SHA-256, then asks Windows for elevation. Background update checks never install or open UAC by themselves.

## What alpha.27 changes

Alpha.27 is a focused UI-hierarchy and gesture-consistency pass on top of alpha.26.

- **Typography is now an app-wide contract.** Page titles, subtitles, section headings, body copy, secondary text, captions and intentional data-value sizes all resolve through the shared `TypographyScale` rather than page-specific numbers.
- **Late-created WPF surfaces inherit the same hierarchy.** Windows, UserControls, ToolTips and dynamically created pages are normalized when they load, so Audio, Touchpad, diagnostics and secondary windows cannot quietly drift from the main shell.
- **Visual QA enforces the typography ramp.** The snapshot release gate validates rendered controls after normalization and fails if ordinary UI text escapes the shared scale.
- **Home battery presentation matches the telemetry hierarchy.** Battery label, percentage and power are left-aligned like CPU/Fans/Power/Sensors, with the larger battery gauge kept as contextual information on the right.
- **Compact and Full use one utility-action order:** view-mode first, notifications second, then the surface-specific hide/close action.
- **Touchpad actions share one visual grammar.** Volume, Brightness, media scrub and Track control declare negative / center / positive meaning through one catalog, while the visualizer owns orientation, spacing, inversion and active-state treatment.
- **Track control is visually cleaner.** Previous, optional center Play/Pause and Next now use the same spacing engine as the other directional actions instead of bespoke coordinates.

Alpha.26 already introduced the broader gesture simplification, async Audio discovery, quieter diagnostics, fan-curve Undo/Redo and the first shared desktop typography scale; alpha.27 turns the visual hierarchy and gesture layout into reusable app-level rules instead of local polish.

| **Updates** | Shared update state, SHA-256 verification and explicit installer handoff |
| **Settings** | App behavior, appearance, diagnostics/privacy, battery-history retention and reset controls |

## Hardware safety and device support

ThinkControl grows support from broad to specific:

`Windows generic → OEM generic → product family → exact model`

Profiles decide which providers are reasonable to probe. Providers own implementation, readback, lifecycle and write safety. Low-level controls remain visible but unavailable until the exact capability is detected and validated.

On the verified X9-15 profile:

- direct fan writes stay restricted to reviewed machine types;
- writes are read back and supervised;
- failed/disposed manual ownership returns to Lenovo/OEM Auto where supported;
- real provider telemetry is preferred over fallback probes;
- sensor/provider failure is reported explicitly rather than replaced by synthetic values.

On an unverified laptop, ThinkControl can quietly learn provider/control compatibility while the user naturally exercises the app. Known devices skip that compatibility-learning workflow and load normally.

See **[Device support](docs/DEVICE-SUPPORT.md)** and **[Hardware safety](docs/HARDWARE-SAFETY.md)**.

## Diagnostics and privacy

Diagnostics are separated into three concerns:

- **Compatibility learning** for an unknown device, until the useful evidence is stable.
- **Crash recovery**, stored locally so a fatal crash can be reviewed on the next healthy launch.
- **Troubleshooting data**, kept local and bounded for support/debugging.

Compatibility reports exclude serial numbers, Windows usernames, hostnames, personal paths and raw personal logs. Nothing is uploaded automatically. Opening a pre-filled GitHub report is an explicit action, and the same semantic report is remembered as handled until new evidence appears.

See **[Diagnostics & privacy](docs/DIAGNOSTICS.md)**.

## Touchpad behavior

Continuous actions are bounded and coalesced rather than issuing an OS write for every raw touch frame. Media seeking uses an accumulated target and controlled write cadence so slow movement can stay precise without flooding media sessions.

The visual trail represents actual continuous contact. A new contact starts a new segment; an implausibly large physical jump also breaks the segment instead of drawing a fake connecting line.

Previous/Next can optionally expose Play/Pause in the center. A skip gesture wins first; center Play/Pause only commits after a near-neutral hold and release, so normal sliding does not accidentally resume media.

## Audio and Dolby

ThinkControl keeps the normal Windows audio path usable even if Dolby integration is unavailable. Output/input discovery is performed away from the UI thread and coalesced so revisiting Audio does not repeatedly block the page on CoreAudio COM activation.

Direct Dolby controls are enabled only when the installed DAX provider exposes a semantic interface ThinkControl can verify. Unsupported DAX builds remain explicit; ThinkControl does not guess private Dolby profile IDs.

## Development and validation

Windows CI restores and builds the solution, runs core tests, executes the real shell-transition smoke and renders the WPF visual-QA matrix before packaging.

```powershell
dotnet restore ThinkControl.slnx
dotnet build ThinkControl.slnx -c Release
.\tools\visual-qa.ps1
```

Packaging and installer workflows additionally validate payload construction, clean install, service start/IPC, in-place updater compatibility and uninstall cleanup before a prerelease is promoted.

Automated CI cannot prove physical-device behavior. Fan ownership/RPM, OEM keyboard readback, touchpad HID behavior, Dolby DAX behavior and haptic response still require validation on the actual target hardware before that exact driver/firmware combination is treated as physically confirmed.
