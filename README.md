## ThinkControl alpha.31

ThinkControl is a lightweight Windows 10/11 companion that starts with verified Lenovo/ThinkPad hardware support while keeping Windows-generic capabilities and provider contracts usable across other laptops. It combines controls normally spread across Windows Settings, OEM utilities and monitoring tools into a fast Compact view and a resizable Advanced view.

**Current prerelease candidate:** `v0.1.0-alpha.31`

**Verified low-level reference:** ThinkPad X9-15 Gen 1 (`21Q6` / `21Q7`)  
**Platform:** Windows 10 version 2004 (build 19041) or newer, x64 · .NET 10

Windows-safe controls can work on more systems, while direct EC/fan and OEM controls stay capability-gated. ThinkControl does not invent RPM values, PWM percentages, sensor readings or guessed hardware registers.

ThinkControl has two primary surfaces:

- **Compact view** — quick telemetry and the controls you change most often.
- **Advanced view** — Home, Performance, Fans, Display, Audio, Keyboard, Battery, Touchpad, System, Updates and Settings.

The release pipeline renders the real WPF interface across dark/light themes and multiple viewport sizes. It also runs real Compact ↔ Advanced lifecycle smoke tests so shell regressions are not hidden by static screenshots.

## Install

Download the newest setup from **[GitHub Releases](https://github.com/Hugowhitee/ThinkControl/releases)**:

```text
ThinkControl-Setup-0.1.0-alpha.31.exe
```

For a normal install, Setup is the only file you need. A clean interactive install lets you choose the install location. Updates preserve the existing location automatically. Each public prerelease also includes the updater payload, `SHA256SUMS.txt` and `ui-overview.png`.

Updates are explicit: ThinkControl downloads Setup + Payload + checksums, verifies SHA-256, then asks Windows for elevation. Background update checks never install or open UAC by themselves.

The release gate exercises a clean custom-location install, hardware-service start and IPC, an in-place update without passing the location again, compatibility with the older alpha.14 updater path, and a full uninstall cleanup.

## What alpha.31 changes

Alpha.31 is a stabilization and architecture-cleanup release following alpha.30. It focuses on crash prevention, touchpad intent, coherent power controls, safer fan calibration and removing one-off release patches from the permanent codebase.

- **The shell crash path is hardened.** Dispatcher callbacks involved in Compact/Advanced transitions use explicit parameterless delegates instead of signatures that WPF can invoke with the wrong parameter count, addressing the reported `TargetParameterCountException` path.
- **Compact/Advanced ownership is deterministic.** Compact remains a topmost utility while visible without forcing owned ThinkControl notifications behind it, and shell transitions show immediate painted feedback rather than a dead click period.
- **Cold startup stays painted.** A dedicated loading surface is visible before synchronous discovery and stays up until the destination has rendered.
- **Home and Compact use the same quick power contract.** Their selector means the battery preference; the full Performance page remains the source of truth for separate battery and AC settings.
- **Home telemetry survives the minimum viewport.** Battery label/ETA spacing and the Performance explanation no longer rely on text that clips at the supported minimum width.
- **Touchpad corner launches now have one physical truth.** The diagonal lanes drawn and clicked in the UI use the exact same millimetre geometry as Core recognition; there is no hidden square corner hitbox.
- **Track control is less trigger-happy.** Previous/Next requires deliberate travel, while optional center Play/Pause has its own bounded low-travel hold/release zone and prefers the active Windows media session with safe fallback.
- **Gesture feedback reflects the real media result.** Play/Pause feedback uses the resulting playback state rather than always showing the same symbol.
- **Keyboard effects no longer race static writes.** X9 keyboard Auto/effects and direct level changes share serialized hardware ownership so in-flight writes are not silently dropped.
- **Fan calibration is transactional.** The verified X9 path measures all seven EC states with three spaced tachometer samples per state, validates the complete candidate, and preserves the previous known-good calibration when a run fails or is cancelled.
- **Calibration UI is capability-gated.** Raw X9 EC controls appear only when the verified X9 provider plus the required write/temperature/tachometer capabilities are active; the old subjective audibility marker is removed.
- **Release-specific UI patches were consolidated.** Alpha-named Home/Compact partials and the generic `ReleasePolish` touchpad owner were folded into permanent feature/layout owners instead of accumulating as historical layers.
- **Repository hygiene is now CI-enforced.** CI rejects broken local Markdown links, tracked build/runtime artifacts, version drift in the main product docs and reintroduction of the consolidated release-specific partials.
- **Documentation has explicit ownership.** Product behavior, cooling/calibration rules, provider research, release procedure and active release-readiness tracking no longer duplicate the same implementation claims across several stale documents.

## Hardware safety and device support

ThinkControl grows support from broad to specific:

`Windows generic → OEM generic → product family → exact model`

Profiles decide which providers are reasonable to probe. Providers own implementation, readback, lifecycle and write safety. Low-level controls remain unavailable until the exact capability is detected and validated.

On the verified X9-15 profile:

- direct fan writes stay restricted to reviewed machine types;
- writes are supervised and returned to Lenovo/OEM Auto on failure/disposal where supported;
- real provider telemetry is preferred over fallback probes;
- calibration requires real tachometer evidence and never persists a partial failed run;
- sensor/provider failure is reported explicitly rather than replaced by synthetic values.

On an unverified laptop, ThinkControl can quietly gather local compatibility evidence while the user naturally exercises supported controls. Known devices skip unnecessary compatibility-learning work. A future shared device-profile service will require repeated independent evidence before promoting hardware-specific behavior; that cloud lifecycle is not part of alpha.31.

See **[Device support](docs/DEVICE-SUPPORT.md)** and **[Hardware safety](docs/HARDWARE-SAFETY.md)**.

## Diagnostics and privacy

Diagnostics are separated into three concerns:

- **Compatibility learning** for an unknown device, until useful evidence is stable.
- **Crash recovery**, stored locally so a fatal crash can be reviewed on the next healthy launch.
- **Troubleshooting data**, kept local and bounded for support/debugging.

Compatibility reports exclude serial numbers, Windows usernames, hostnames, personal paths and raw personal logs. In alpha.31 nothing is uploaded automatically. Opening a pre-filled GitHub report is an explicit action, and the same semantic report is remembered as handled until new evidence appears.

See **[Diagnostics & privacy](docs/DIAGNOSTICS.md)**.

## Touchpad behavior

Continuous actions are bounded and coalesced rather than issuing an OS write for every raw touch frame. Media seeking uses an accumulated target and controlled write cadence so slow movement can stay precise without flooding media sessions.

The visual trail represents actual continuous contact. A new contact starts a new segment; an implausibly large physical jump also breaks the segment instead of drawing a fake connecting line.

Previous/Next can optionally expose Play/Pause in the center. A deliberate skip gesture wins first; center Play/Pause only commits after low-travel hold-and-release inside its visible bounded zone. Optional top-corner launches use separate diagonal lanes whose visible geometry and recognizer hitbox share one Core policy.

## Audio and Dolby

ThinkControl keeps the normal Windows audio path usable even if Dolby integration is unavailable. Output/input discovery is performed away from the UI thread and coalesced so revisiting Audio does not repeatedly block the page on CoreAudio COM activation.

Direct Dolby controls are enabled only when the installed DAX provider exposes a semantic interface ThinkControl can verify. Unsupported DAX builds remain explicit; ThinkControl does not guess private Dolby profile IDs.

## Development and validation

Windows CI runs repository-hygiene checks, restores and builds the solution, runs core tests, executes the real shell-transition smoke and renders the WPF visual-QA matrix before packaging.

```powershell
.\tools\repository-hygiene.ps1
dotnet restore ThinkControl.slnx
dotnet build ThinkControl.slnx -c Release
.\tools\visual-qa.ps1
```

Packaging and installer workflows additionally validate payload construction, custom-location clean install, service start/IPC, in-place updater compatibility and uninstall cleanup before a prerelease is promoted.

Automated CI cannot prove physical-device behavior. Fan ownership/RPM, OEM keyboard readback, touchpad HID behavior, Dolby DAX behavior and haptic response still require validation on the actual target hardware before that exact driver/firmware combination is treated as physically confirmed.
