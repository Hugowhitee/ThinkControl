## ThinkControl alpha.36

ThinkControl is a lightweight Windows 10/11 companion that starts with verified Lenovo/ThinkPad hardware support while keeping Windows-generic capabilities and provider contracts usable across other laptops. It combines controls normally spread across Windows Settings, OEM utilities and monitoring tools into a fast Compact view and a resizable Advanced view.

**Current prerelease candidate:** `v0.1.0-alpha.36`

**Verified low-level reference:** ThinkPad X9-15 Gen 1 (`21Q6` / `21Q7`)  
**Platform:** Windows 10 version 2004 (build 19041) or newer, x64 · .NET 10

Windows-safe controls can work on more systems, while direct EC/fan and OEM controls stay capability-gated. ThinkControl does not invent RPM values, PWM percentages, sensor readings or guessed hardware registers/IOCTLs.

- **Advanced view** — Home, Performance, Fans, Battery, Display, Audio, Keyboard, Touchpad, System, Updates and Settings.

The release pipeline renders the real WPF interface across dark/light themes and multiple viewport sizes. It also runs real Compact ↔ Advanced lifecycle smoke tests so shell regressions are not hidden by static screenshots.

## Install

Download the newest setup from **[GitHub Releases](https://github.com/Hugowhitee/ThinkControl/releases)**:

```text
ThinkControl-Setup-0.1.0-alpha.36.exe
```

For a normal install, Setup is the only file you need. A clean interactive install lets you choose the install location. Updates preserve the existing location automatically. Each public prerelease also includes the updater payload, `SHA256SUMS.txt` and `ui-overview.png`.

Updates are explicit: ThinkControl downloads Setup + Payload + checksums, verifies SHA-256, then asks Windows for elevation. Background update checks never install or open UAC by themselves.

## What alpha.36 changes

Alpha.36 combines the post-alpha.35 Touchpad corner work with the X9 dual-fan/native-provider hardening. The release keeps risky hardware behavior capability-gated and preserves Lenovo/OEM Auto as the fail-safe.

- **Touchpad corner launches are part of the same six-zone editor now.** Top-left and top-right use one exact mirrored guard → diagonal lane → rounded end-cap geometry instead of looking/behaving like a separate overlay.
- **Corner reliability is improved.** An enabled corner owns eligible first-frame input before the adjacent top/side edge, and a rejected corner stays locked out until lift instead of turning into the wrong edge gesture.
- **Corner visuals are clearer.** The old flat divider/blob treatment is replaced by a directional arrow, rounded end arc and Compact/Advanced semantic icon/text.
- **Optional reverse-close is available per corner.** Starting in the rounded inner cap and swiping back toward the physical corner can hide the visible Compact/Advanced shell when explicitly enabled.
- **The X9 fan model now understands two physical fans.** Fan 1 / Fan 2 telemetry is preserved independently where a real provider exposes both channels.
- **Lenovo-native fan semantics take priority over the old seven-step EC assumption.** A capability-gated `LENOVO_OTHER_METHOD` provider can use direct per-fan target RPM when the exact X9 exposes at least two VALID+GET+SET channels with sane Lenovo constraints and live reads.
- **Direct OEM percentages are real target-RPM requests, not renamed EC steps.** When that provider is active, curves/manual targets map across each fan's Lenovo-reported RPM range and target `0` returns the owned channels to Lenovo Auto.
- **EnergyDrv is used read-only until its writer is actually understood.** `QueryFanSpeed 0x83102570` can provide native two-fan telemetry; the separate `ChangeFanSpeed 0x8310257C` write command remains blocked until exact X9 command/rollback semantics are recovered.
- **The known-inferior EC writer no longer wins over proven native two-fan evidence.** Native fan proof is latched for the hardware-service lifetime so a transient query miss cannot silently re-enable EC control.
- **Fan ownership/rollback is stricter.** ThinkControl tracks the provider/channels it actually wrote and only releases those owned channels to Auto; reading another tool's manual-looking state is not treated as ownership.
- **Stale RPM presentation is reduced.** Fan-state changes invalidate old RPM samples before settled replacements are shown, while visible-page refresh remains bounded and does not become a high-rate EC polling loop.
- **Diagnostics/research are more useful without adding unsafe writes.** Bounded fan samples preserve provider/source details, and the Lenovo Auto capture/static analyzer can inspect Other Mode, EnergyDrv, LITSSVC and selected OEM binaries without brute-forcing fan commands.
- **Release validation remains consolidated.** CI owns build/tests/shell/visual QA; Package ThinkControl owns payload/installer/service/IPC/update/uninstall and oldest-supported updater compatibility.

The direct Lenovo target-RPM path is deliberately self-gating. Hosted CI can prove code/lifecycle safety but cannot prove how a particular X9 BIOS/Lenovo software stack exposes or physically responds to that provider. If it is unavailable, ThinkControl remains on a safer telemetry/fallback state rather than guessing a command.

## Main capabilities

| Area | What ThinkControl provides |
| --- | --- |
| **Home** | Live Battery, CPU, fan/RPM, power and sensor overview plus quick controls |
| **Performance** | Separate battery and plugged-in preferences using Windows power integration |
| **Fans** | OEM Auto, supervised curves and verified manual/calibration controls only where the active provider supports them |
| **Battery** | Watts, Wh, health, ETA, temperature when genuinely exposed, and compact local charge/discharge history |
| **Display** | Brightness, adaptive brightness, refresh rate, automatic refresh switching and Windows display shortcuts |
| **Audio** | Windows output/microphone control plus semantic Dolby controls where the installed DAX provider safely exposes them |
| **Keyboard** | Verified hardware levels, Lenovo firmware Auto where exposed, and bounded direct-provider user-session effects |
| **Touchpad** | Live contact visualization, a unified six-zone edge/corner editor, haptics and bounded gesture feedback |
| **System** | Device/provider state, repair flow and detailed sensor telemetry |
| **Updates** | Shared update state, SHA-256 verification and explicit installer handoff |
| **Settings** | App behavior, appearance, diagnostics/privacy, battery-history retention and reset controls |

## Hardware safety and device support

ThinkControl grows support from broad to specific:

`Windows generic → OEM generic → product family → exact model`

Profiles decide which providers are reasonable to probe. Providers own implementation, readback, lifecycle and write safety. Low-level controls remain unavailable until the exact capability is detected and validated.

On the X9-15 path:

- direct fan writes stay restricted to reviewed machine types and provider-specific gates;
- Lenovo-native target-RPM control is preferred when two independently live/constrained writable channels are exposed;
- native two-fan telemetry can remain read-only without pretending the matching writer is known;
- seven-step EC control is an explicit fallback/investigation provider rather than a fake continuous maximum;
- writes are supervised and returned to Lenovo/OEM Auto on failure/disposal where supported;
- real provider telemetry is preferred over fallback probes;
- calibration requires real tachometer evidence and never persists a partial failed run;
- PawnIO registration/service/device readiness is distinguished instead of collapsed into one registry check;
- sensor/provider failure is reported explicitly rather than replaced by synthetic values.

Automated CI does **not** prove physical-device behavior. X9 direct-RPM activation/range, final hot-Auto comparison, clean PawnIO repair/restart behavior, Lenovo Auto/Fn+Space agreement, touchpad feel, Dolby behavior and haptics still require validation on the actual target hardware before that exact driver/firmware combination is treated as physically confirmed.

See **[Device support](docs/DEVICE-SUPPORT.md)** and **[Hardware safety](docs/HARDWARE-SAFETY.md)**.

## Diagnostics and privacy

Diagnostics are separated into compatibility learning, crash recovery and troubleshooting data. Compatibility reports exclude serial numbers, Windows usernames, hostnames, personal paths and raw personal logs. Nothing is silently uploaded by the alpha client; opening a pre-filled GitHub report is explicit.

See **[Diagnostics & privacy](docs/DIAGNOSTICS.md)**.

## Development and validation

Windows CI runs repository-hygiene checks, restores and builds the solution, runs Core tests, executes the real shell-transition smoke and renders the WPF visual-QA matrix before packaging.

```powershell
.\tools\repository-hygiene.ps1
dotnet restore ThinkControl.slnx
dotnet build ThinkControl.slnx -c Release
.\tools\visual-qa.ps1
```

Packaging and installer workflows additionally validate payload construction, custom-location clean install, service start/IPC, updater compatibility and uninstall cleanup before a prerelease is promoted.
