# ThinkPad X9-15 Gen 1 research

Machine types: `21Q6` and `21Q7`.

This document records the hardware findings used by the ThinkControl X9 provider. It is a research record, not a general-purpose register map for other Lenovo devices.

## Fan interface

Prior X9 testing established the classic ThinkPad EC interface:

```text
Fan control register   0x2F
Tachometer low byte    0x84
Tachometer high byte   0x85
Lenovo Auto            0x80
Manual levels          1 to 7
```

Safety policy:

```text
0x00 fan off            blocked
0x40 override family    blocked and unverified
0 to 100 percent PWM    no verified interface found
```

The working implementation uses PawnIO-backed I/O, tolerant EC reads, paced writes, duplicate-write suppression and the standard ThinkPad EC mutexes. Modern ThinkPad Type 1 ports `0x1604/0x1600` are probed read-only before the older `0x66/0x62` fallback. A port pair is accepted only after a plausible ThinkPad fan-control state is read.

## Tachometer behavior

The X9 tachometer occasionally failed to return both bytes reliably when `0x84` and `0x85` were accessed too aggressively. Repeated high-frequency RPM polling also correlated with periodic audible fan disturbance. ThinkControl therefore treats RPM as low-rate telemetry rather than a control-loop clock.

The X9-15 cooling assembly physically contains two fans. TPFanCtrl2 supports some dual-fan ThinkPads by writing selector register `0x31` before reading the shared `0x84/0x85` tachometer. That selector write has **not** been physically verified for the X9-15, so ThinkControl deliberately does not use it. The current UI exposes the one verified system-fan tachometer reading instead of inventing a second RPM value or adding an unverified selector write.

## Read-only EC thermal fallback

Classic ThinkPad EC implementations expose thermal bytes at `0x78..0x7F` and `0xC0..0xC3`. ThinkControl may read plausible `5..125 °C` values from these banks on the already-validated X9 EC transport when LibreHardwareMonitor does not provide a usable CPU/GPU control temperature.

These registers remain deliberately **unmapped** in the public telemetry model:

- Sensors labels them as generic `EC thermal 0x..` readings;
- they are never relabeled as `CPU Package` without device-specific evidence;
- `CpuTemperatureC` remains sourced from a provider that identifies CPU hardware;
- the fan supervisor may use the hottest valid EC thermal value as a conservative safety/control fallback when richer temperature telemetry is unavailable.

This keeps custom cooling usable during a sensor-provider gap without lying about what a particular EC byte represents.

## Fan interfaces ruled out for the X9

Earlier diagnostics did not find a better continuous fan-control interface on the reference X9:

- no usable Legion-style WMI fan-control interface;
- Intel IGCL reported no chassis fan interface;
- standard ACPI `_FSL` control was absent;
- Lenovo `FANG` and `FANW` methods were absent;
- `IBMPmDrv` `GSFF/SSFF` did not provide the required X9 fan backend.

## Lenovo Intelligent Thermal Solution

Observed components:

```text
Service       LITSSVC
ACPI device   ACPI\LEN0100
ACPI path     \_SB.PC00.LPCB.EC.ITSD
Version seen  2.2.111.0
```

This is a Lenovo thermal-policy layer rather than a direct PWM fan interface.

## ThinkSmartSense and LITS IPC

The observed path is:

```text
Commercial Vantage
  -> ThinkSmartSenseAddin
  -> \\.\pipe\com.lenovo.its.pipe.setting
  -> LITSSvc
```

IL inspection showed `IntelligentCoolingPipe.ChangeITSsetting(UInt32)` connecting to the pipe, writing one UInt32, flushing and reading one Int32 response. No JSON or complex framing is used.

Known command IDs include:

```text
AC Eco           502
AC Balanced      503
AC Performance   504
DC Eco           507
DC Balanced      508
DC Performance   509
```

ThinkControl uses only these six commands and only after the privileged service independently confirms X9 machine type `21Q6` or `21Q7`.

The UI sends the semantic mode `Quiet`, `Balanced` or `Performance`; it cannot send a raw Lenovo command ID. The service reads AC/DC state and maps the request to the allowlisted command.

Lenovo has not published the Int32 response-value semantics. ThinkControl therefore treats receipt of the complete response as the protocol readback boundary and does not invent a success rule based on the integer value.

This policy coordination runs after a successful Windows power-mode change. It is not used as fake direct fan-speed control.

## Windows Energy mode traces

A Process Monitor capture on battery while manually changing Windows Energy mode showed `LITSSvc.exe` updating `LITSSVC\IC\PSC\CurrentSetting`:

```text
Best power efficiency -> CurrentSetting 4
Balanced              -> CurrentSetting 6
Best performance      -> CurrentSetting 8
```

A broader trace also showed Intel Innovation Platform Framework activity in the Windows energy-mode path. This supports keeping Windows power mode as the primary OS-level policy interface while treating Lenovo LITS coordination as an X9-specific OEM policy layer.

## Lenovo Power Management

Observed on the X9:

```text
Service  IBMPMSVC
Device   \\.\IBMPmDrv
```

This interface is used for supported functions such as keyboard backlight where a command contract and readback are established. No generic IOCTL guessing is permitted.

`LITSSvc.exe` also referenced `\\.\EnergyDrv`; ThinkControl uses only established/readback-validated keyboard contracts and does not expose arbitrary driver calls.

## Current architecture model

```text
Windows Energy mode
    -> Windows / Intel IPF platform policy
    -> Lenovo LITS may mirror/react

ThinkControl X9 Quiet/Balanced/Performance
    -> Windows power mode
    -> semantic ThinkControl service request
    -> X9 identity gate + AC/DC detection
    -> allowlisted LITSSvc 502/503/504/507/508/509 policy command

Direct X9 fan control
    -> verified PawnIO device/module handshake
    -> detected ThinkPad EC port pair
    -> verified fan register 0x2F
    -> levels 1..7 or Lenovo Auto 0x80 with readback

X9 telemetry fallback
    -> verified EC tachometer 0x84/0x85 at low rate
    -> generic read-only EC thermal banks when LHM control temperature is absent
```

The policy paths remain separate from direct fan control.
