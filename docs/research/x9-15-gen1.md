# ThinkPad X9-15 Gen 1 research

Machine types: `21Q6` and `21Q7`.

This document records the hardware findings used to build the first ThinkControl X9 provider. It is a research record, not a general-purpose register map for other Lenovo devices.

## Fan interface

Prior X9 testing established the following classic ThinkPad EC interface:

```text
Fan control register   0x2F
Tachometer low byte    0x84
Tachometer high byte   0x85
Lenovo Auto            0x80
Manual levels          1 to 7
```

Safety policy:

```text
0x00 fan off            blocked
0x40 override family    blocked and unverified
0 to 100 percent PWM    no verified interface found
```

The working research implementation used PawnIO-backed I/O, tolerant EC reads, paced writes, duplicate-write suppression and the standard ThinkPad EC mutexes.

Repeated unchanged fan writes were avoided because they can cause the EC to re-evaluate the current fan state.

## Tachometer behavior

The X9 tachometer occasionally failed to return both bytes reliably when `0x84` and `0x85` were accessed too aggressively. The research implementation used a small delay and retry path.

Repeated high-frequency RPM polling also correlated with a periodic audible fan disturbance during testing. ThinkControl therefore treats RPM as low-rate telemetry rather than a control-loop clock.

## Fan interfaces that were not suitable

Earlier diagnostics did not find a better continuous fan-control interface on the reference X9:

- no usable Legion-style WMI fan-control interface;
- Intel IGCL reported no chassis fan interface;
- standard ACPI `_FSL` control was absent;
- Lenovo `FANG` and `FANW` methods were absent;
- `IBMPmDrv` `GSFF/SSFF` did not provide the required X9 fan backend.

## Lenovo Intelligent Thermal Solution

Observed components:

```text
Service       LITSSVC
ACPI device   ACPI\LEN0100
ACPI path     \_SB.PC00.LPCB.EC.ITSD
Version seen  2.2.111.0
```

This appears to be a Lenovo thermal-policy layer rather than a direct PWM fan interface.

## ThinkSmartSense and LITS IPC

The following path was observed during earlier analysis:

```text
Commercial Vantage
  -> ThinkSmartSenseAddin
  -> \\.\pipe\com.lenovo.its.pipe.setting
  -> LITSSvc
```

The observed protocol writes a `UInt32` command and reads an `Int32` result.

Known command IDs from that research include:

```text
AC Eco           502
AC Balanced      503
AC Performance   504
DC Eco           507
DC Balanced      508
DC Performance   509
```

These values remain device or family specific until separately validated inside ThinkControl. They are not used as a universal Lenovo control interface.

## Intel Innovation Platform Framework

Intel Innovation Platform Framework was present in the Windows energy-mode path. ThinkControl should continue to use supported Windows power APIs rather than private IPF control calls. IPF presence and version can still be useful diagnostic information.

## Lenovo Power Management

Observed on the X9:

```text
Service  IBMPMSVC
Device   \\.\IBMPmDrv
```

This Lenovo PM interface is used for supported functions such as keyboard backlight where the command contract has been established and readback is available.

No generic IOCTL guessing is permitted.

## Additional research leads

`LITSSvc.exe` referenced `\\.\EnergyDrv` and `DeviceIoControl`. This remains a research lead rather than a production X9 backend.

`LenovoVantageService` was present on the reference system. ThinkControl prefers supported Windows APIs or an established Lenovo provider contract over undocumented Vantage IPC.

`ImControllerService` was not present on the reference X9, so X9 support must not depend on the older ImController/System Interface Foundation stack.
