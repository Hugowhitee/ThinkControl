# ThinkPad X9-15 Gen 1 research record

Machine types: **21Q6 / 21Q7**.

This document preserves conclusions from the earlier X9 Helper and Thinkpad_Fancontrol work. It is research input, not permission for arbitrary writes.

## Verified fan interface from prior testing

Classic ThinkPad EC interface:

```text
fan control register    0x2F
fan tach low            0x84
fan tach high           0x85
Lenovo BIOS/EC Auto     0x80
manual levels           1-7
```

Safety decisions:

```text
0x00 fan-off             blocked
0x40 disengaged/override blocked/unverified
continuous 0-100% PWM    not found
```

The working research implementation used PawnIO-backed I/O, tolerant EC reads, TPFC-style write pacing, duplicate-write suppression and shared EC mutexes. Repeated unchanged writes were specifically avoided because they can cause the EC to re-evaluate/ramp the fan.

The X9 tachometer occasionally missed the second byte when 0x84/0x85 were read too aggressively. The research code inserted a small gap and retries. More importantly, repeated multi-second tachometer polling correlated with an audible `puff/puff` cadence, so ThinkControl must treat RPM reads as potentially intrusive telemetry.

## Negative fan-interface findings

Prior diagnostics did not find a better native continuous fan API:

- no usable Legion WMI fan-control interface
- Intel IGCL enumerated zero chassis fans
- standard ACPI `_FSL` fan control was absent
- Lenovo `FANG/FANW` methods were absent
- `IBMPmDrv` `GSFF/SSFF` behaved like legacy/stub functionality and was not the X9 fan backend

## Lenovo Intelligent Thermal Solution

Observed on the X9:

```text
Service: LITSSVC
ACPI device: ACPI\LEN0100
ACPI path: \_SB.PC00.LPCB.EC.ITSD
Observed version during research: 2.2.111.0
```

This is a **thermal-policy backend**, not direct PWM fan control.

## ThinkSmartSense / LITS IPC

Observed path:

```text
Commercial Vantage
  -> ThinkSmartSenseAddin
  -> \\.\pipe\com.lenovo.its.pipe.setting
  -> LITSSvc
```

Observed protocol shape: write a `UInt32` command and read an `Int32` result.

Known command IDs from prior research include:

```text
AC Eco          502
AC Balanced     503
AC Performance  504
DC Eco          507
DC Balanced     508
DC Performance  509
```

Treat these as device/family-specific until revalidated inside ThinkControl. A `PerformanceCoordinator` must prevent Windows Energy Mode and LITS policy from fighting each other.

## Intel Innovation Platform Framework

Observed in the Windows Energy Mode path. ThinkControl should use supported Windows power-mode APIs rather than private IPF calls. IPF presence/version is useful for diagnostics.

## Lenovo Power Management

Observed:

```text
Service: IBMPMSVC
Device: \\.\IBMPmDrv
```

This is a Lenovo PM/ACPI bridge and may support verified features such as keyboard backlight/Fn settings. Production use requires a proven command per model/family. No generic IOCTL guessing.

## Research-only leads

`LITSSvc.exe` referenced `\\.\EnergyDrv` and DeviceIoControl. This remains a research lead, not a production backend.

`LenovoVantageService` was present on the X9. It can initially be reported as software status; undocumented IPC is not preferred when a supported Windows/LITS path exists.

`ImControllerService` was not present on the X9. ThinkControl must not depend on the older ImController/System Interface Foundation stack for X9 support.
