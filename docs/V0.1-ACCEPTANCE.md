# v0.1 acceptance criteria

## Definition

`v0.1` is the **foundation milestone**, not the first full fan-control release. It exists to make later low-level features difficult to implement unsafely.

## Must pass before v0.1 is tagged

### Repository and build

- [ ] .NET 10 solution restores and builds in Release on `windows-latest`.
- [ ] CI runs on pull requests and relevant branches.
- [ ] UI, Service, Core, Hardware and DeviceProfiles projects have the documented dependency direction.
- [ ] No secrets, certificates or machine-specific dumps are committed.

### Architecture

- [ ] WPF UI is a normal-user process.
- [ ] privileged operations are owned by the Service project.
- [ ] the named-pipe protocol is versioned and authorizes clients with Windows identity/ACLs.
- [ ] IPC exposes semantic operations only; no raw EC/port/IOCTL passthrough.
- [ ] hardware providers implement Core contracts rather than calling UI code.

### Device support

- [ ] read-only device identity can distinguish the X9-15 reference profile from an unknown ThinkPad without using serial number.
- [ ] capability resolution has explicit unavailable/read-only/verified/conflict states.
- [ ] unknown devices receive no unverified hardware-write capability.
- [ ] the X9 research profile is bundled and schema-versioned.

### Safety

- [ ] there is **no active EC write implementation in v0.1**.
- [ ] X9 safety allow/block rules are represented in tests or validated profile parsing before the EC backend is introduced.
- [ ] diagnostics redaction rules cover serial, user name, host name, MAC and disk serial.
- [ ] future direct fan control has a required `ReturnToAuto` semantic operation in its contract.
- [ ] conflict state is part of the capability model.

### Reliability foundation

- [ ] service lifecycle design includes sleep/resume and shutdown hooks.
- [ ] logging locations are separated for UI and service and use bounded rolling files once logging is implemented.
- [ ] updater design requires checksum verification and an explicit user action.

### UX foundation

- [ ] theme tokens support System / Light / Dark without hard-coded per-screen colors.
- [ ] compact and Advanced surfaces use the rules in `DESIGN.md`.
- [ ] no unsupported/inert hardware controls are shipped.

### Documentation

- [ ] architecture, product, hardware-safety, design and device-support docs are current.
- [ ] X9 research conclusions and unverified leads are clearly separated.

## Explicitly not required for v0.1

- fan RPM implementation
- EC fan writes
- PawnIO installation flow
- LITS command execution
- keyboard backlight writes
- battery threshold writes
- production installer
- public update channel

Those begin only after the foundation criteria above are satisfied.
